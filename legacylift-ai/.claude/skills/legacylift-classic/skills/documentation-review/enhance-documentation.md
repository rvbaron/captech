## Overview

This skill reads the `07-DOCUMENTATION-ACCURACY-REPORT.md` generated by the `/legacylift-classic:documentation-review` skill and automatically corrects identified issues in the LegacyLift documentation. It addresses inaccurate claims, partial matches, and outdated information by comparing documented claims against the actual code evidence provided in the report.

**Prerequisites:**
- Must have run `/legacylift-classic:documentation-review` first to generate the accuracy report
- The `07-DOCUMENTATION-ACCURACY-REPORT.md` must exist in the documentation folder

## Usage

```
/enhance-documentation docs_path=<path>
```

### Parameters

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `docs_path` | No | Auto-detect | Path to documentation folder containing the accuracy report |

### Examples

```bash
# Fix documentation in a specific repo
/enhance-documentation docs_path=repos/my_project/legacylift-docs

# Auto-detect docs folder in current directory
/enhance-documentation
```

## Fix Patterns

### Pattern 1: Date/Number Correction

**Trigger**: Report shows date or numeric value mismatch

**Example Finding**:
```
Documented: "effective from 2024-01-01"
Actual: Code shows '2016-01-01'
```

**Fix Action**:
```python
Edit file at line X:
  old: "2024-01-01"
  new: "2016-01-01"
```

### Pattern 2: Code Reference Update

**Trigger**: Line number citation is incorrect

**Example Finding**:
```
Documented: "See delta_lake.sql:100"
Actual: Code is at delta_lake.sql:150
```

**Fix Action**:
```python
Edit file:
  old: "delta_lake.sql:100"
  new: "delta_lake.sql:150"
```

### Pattern 3: Terminology Correction

**Trigger**: Technical term or name is wrong

**Example Finding**:
```
Documented: "PostgreSQL database"
Actual: Uses MySQL
```

**Fix Action**:
```python
Edit file:
  old: "PostgreSQL"
  new: "MySQL"
```

### Pattern 4: Wording Clarification

**Trigger**: Partial accuracy - wording is ambiguous

**Example Finding**:
```
Documented: "ratio must equal 0.5"
Actual: Reverts when ratio does NOT equal 0.5
```

**Fix Action**:
```python
Edit file:
  old: "ratio must equal 0.5"
  new: "ratio must equal 0.5 (behavior changes are reverted when ratio differs)"
```

### Pattern 5: Missing Detail Addition

**Trigger**: Claim is incomplete

**Example Finding**:
```
Documented: "Uses staging tables"
Actual: Uses 15+ specific staging tables in de_intermedial schema
```

**Fix Action**:
```python
Edit file to add detail after existing text:
  "Uses staging tables in the `de_intermedial` schema (15+ tables including behavior_change_d_stg, realized_savings_f_stg, etc.)"
```

## Error Handling

| Error | Handling |
|-------|----------|
| Accuracy report not found | Exit with instructions to run /legacylift-classic:documentation-review first |
| No actionable findings | Report success - documentation is accurate |
| Evidence file not found | Skip fix, log to manual review |
| Edit fails | Retry once, then log to manual review |
| Document not found | Skip, log warning |

## Safety Rules

1. **Never delete content** - Only modify or add
2. **Preserve structure** - Don't change document organization
3. **Cite evidence** - When adding/changing claims, include code references
4. **Backup awareness** - Remind user to commit before running
5. **Verification** - Always recommend re-running /legacylift-classic:documentation-review after
