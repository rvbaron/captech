# Table of Definitions

Auto-extracts abbreviations, domain-specific jargon, and technical terms from LegacyLift documentation files and appends a **Table of Definitions** section at the end of each document, just before the footer.

## Examples

```
# Process all markdown files in the default legacylift-docs/ folder
/legacylift-classic:table-of-definitions

# Process all markdown files in a specific docs folder
/legacylift-classic:table-of-definitions path=repos/behavior_change_savings/legacylift-docs/

# Process a single file
/legacylift-classic:table-of-definitions path=repos/my_project/legacylift-docs/ file=EXECUTIVE-SUMMARY.md
```

## Parameters

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `path` | No | `legacylift-docs/` | Path to documentation folder containing markdown files |
| `file` | No | (all `.md` files) | Specific file to process (e.g., `EXECUTIVE-SUMMARY.md`). If omitted, processes all `.md` files in `path` |

## Behavior Rules

1. **Skip if exists**: If a document already contains a `## Table of Definitions` section, skip it entirely and report that it was skipped.
2. **Placement**: Insert immediately before the document footer (`---\n\n*Generated By LegacyLift AI by CapTech*`). If a `## Related Documents` section exists, the Table of Definitions goes **after** Related Documents but before the footer.
3. **Output format**: Markdown table with columns `| Term | Definition |`, sorted alphabetically by term.
4. **Minimum threshold**: At least 3 terms must be extracted to warrant adding a section. If fewer than 3 terms are found, skip the file.

## Documentation Process

### Phase 1: Discovery

1. Glob for `*.md` files in `path` (or use single `file` parameter).
2. Read each file.
3. Check for existing `## Table of Definitions` section — skip file if found.

```
Glob: pattern="*.md" path=<target_directory>
```

For each file, read the content and check:
```
if "## Table of Definitions" in file_content:
    report: "skipped (already exists)"
    continue to next file
```

### Phase 2: Extract Terms

Scan document content for terms using these patterns (in priority order):

**Pattern A — Parenthetical acronym definitions:**

Matches like `Pharmacy Benefit Manager (PBM)` or `Extract-Transform-Load (ETL)`.

```
regex: ([A-Z][A-Za-z\s&/,.-]+?)\s*\(([A-Z]{2,}[A-Za-z0-9]*)\)
```

Result: Term = acronym (e.g., `PBM`), Definition = full form (e.g., `Pharmacy Benefit Manager`).

**Pattern B — Acronym-first definitions:**

Matches like `SCD (Scenario Custom Defaults)` or `MYW (Med Your Way)`.

```
regex: \b([A-Z]{2,}[A-Za-z0-9]*)\s*\(([^)]{3,})\)
```

Result: Term = acronym (e.g., `SCD`), Definition = parenthetical text (e.g., `Scenario Custom Defaults`).

**Deduplication note for Patterns A and B:** These patterns overlap. To deduplicate, normalize as follows: if the parenthetical text is all-caps (2+ chars), Pattern A applies (the parenthetical is the acronym). Otherwise Pattern B applies (the parenthetical is the definition).

**Pattern C — Bold-defined table rows:**

Matches markdown table rows like `| **TS** | Tablet Split | description |`.

```
regex: ^\|\s*\*\*([A-Z]{2,})\*\*\s*\|\s*([^|]+)\s*\|
```

Result: Term = bold code (e.g., `TS`), Definition = next column text (e.g., `Tablet Split`).

**Pattern D — Inline bold definitions:**

Matches like `**behavior change** - Medication therapy management...` or `**staging table**: Intermediate processing layer`.

```
regex: \*\*([a-z][a-z\s_]+)\*\*\s*[-–:]\s*([^.\n]{10,}?)(?:\.|$)
```

Result: Term = bold text, Definition = following description.

### Phase 3: Deduplicate and Clean

1. **Normalize terms**: Trim whitespace, collapse duplicates (keep the first/best definition found).
2. **Filter out noise**:
   - Skip single-character terms.
   - Skip terms that are just numbers or file references.
   - Skip terms that appear inside code citations (`[📄](...)`).
   - Skip common English words that happen to match patterns: `IT`, `IS`, `OR`, `AS`, `IF`, `AT`, `TO`, `BY`, `DO`, `GO`, `IN`, `NO`, `OF`, `ON`, `SO`, `UP`, `US`, `WE`.
3. **Sort alphabetically** by term (case-insensitive).
4. **Minimum threshold**: If fewer than 3 terms are found, skip the file and report `skipped (< 3 terms)`.

### Phase 4: Insert Table of Definitions

For each file with 3+ extracted terms:

1. **Locate the footer**: Find the footer pattern `---\n\n*Generated By LegacyLift AI by CapTech*` (or just `*Generated By LegacyLift AI by CapTech*`).

2. **Build the section**:

```markdown

---

## Table of Definitions

| Term | Definition |
|------|------------|
| **API** | Application Programming Interface |
| **ETL** | Extract-Transform-Load |
| **PBM** | Pharmacy Benefit Manager |
```

3. **Insert using Edit tool**: Replace the footer marker with `[Table of Definitions section]\n\n[footer]`.

   - If `## Related Documents` exists, the Table of Definitions goes **after** Related Documents but **before** the footer.
   - If no `## Related Documents` exists, the Table of Definitions goes immediately before the footer.

   Use the Edit tool to find the footer and replace it with the Table of Definitions section followed by the original footer.

4. **Update the Table of Contents**: After inserting the Table of Definitions section, check whether the document contains a `## Table of Contents` section with numbered or bulleted links.

   - If a `## Table of Contents` section exists, append a new entry linking to the Table of Definitions at the **end** of the existing ToC list.
   - Detect the list format used (numbered `1.` or bulleted `-`/`*`) and match it.
   - For **numbered lists**, determine the next number by finding the last numbered entry in the ToC and incrementing by one. Insert:
     ```
     N. [Table of Definitions](#table-of-definitions)
     ```
   - For **bulleted lists**, insert:
     ```
     - [Table of Definitions](#table-of-definitions)
     ```
   - The new entry must be placed as the **last item** in the ToC list, immediately after the current last entry and before any blank line or next section heading that follows the ToC.
   - If the ToC already contains a `[Table of Definitions]` link, skip this step for that file.
   - If no `## Table of Contents` section exists, skip this step (no ToC to update).

## Output

For each file processed, report:

| Field | Description |
|-------|-------------|
| **File name** | Name of the markdown file |
| **Terms extracted** | Count of terms found |
| **Status** | `added` / `skipped (already exists)` / `skipped (< 3 terms)` |

Example output:

```
Processing results:
  EXECUTIVE-SUMMARY.md        — 12 terms — added
  SYSTEM-ARCHITECTURE.md      — 8 terms  — added
  BUSINESS-RULES.md           — skipped (already exists)
  QUICK-REFERENCE.md          — 2 terms  — skipped (< 3 terms)
```

## Verification

After all files are processed:

1. **Confirm sections added**: Grep for `## Table of Definitions` in all processed files to verify sections were inserted.

```
Grep: pattern="## Table of Definitions" path=<target_directory>
```

2. **Confirm footer intact**: Grep for the footer in every file to verify it was preserved.

```
Grep: pattern="Generated By LegacyLift AI by CapTech" path=<target_directory>
```

## Quality Checklist

After all files are processed, confirm:

- [ ] Table of Definitions section is present in all files that had 3+ extractable terms
- [ ] Terms are sorted alphabetically with no duplicates
- [ ] Common English words (`IT`, `IS`, `OR`, etc.) are excluded
- [ ] Footer (`*Generated By LegacyLift AI by CapTech*`) is intact in every processed file
- [ ] Files with existing Table of Definitions sections are untouched
- [ ] Table of Contents updated with a `[Table of Definitions]` link where applicable
- [ ] Verification grep confirms sections added and footers intact
