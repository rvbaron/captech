# Doc Exporter

This skill converts markdown documentation in a repository's `legacylift-docs/` directory into professionally styled Word (.docx) or PDF (.pdf) documents using Pandoc. It supports two modes: **individual** (one output file per markdown file) and **consolidated** (a single combined document).

## Parameters

Parse the following parameters from the user's invocation:

- **format** — `word` (default) or `pdf`. Determines output file type (`.docx` or `.pdf`).
- **mode** — `individual` (default) or `consolidated`. Determines whether each `.md` file produces its own output or all are merged into one document.
- **path** — Custom repository path. Defaults to the current working directory.
- **file** — (Optional) Specific `.md` filename to export (e.g., `file=00-EXECUTIVE-SUMMARY.md`). When provided, only this single file is exported instead of all files in the directory. Works with both `individual` and `consolidated` modes (though consolidated with a single file behaves the same as individual).

## Instructions

When invoked, execute the following phases in order:

### Phase 1: Discover Documentation

1. Look for a `legacylift-docs/` directory in the current working directory (or a path provided by the user).
2. If not found, fall back to a `docs/` directory.
3. If the **file** parameter is provided, locate only that specific file in the docs directory. If the file does not exist, stop and inform the user.
4. Otherwise, list all `.md` files sorted alphabetically.
5. Report the number of files found. If none are found, stop and inform the user.

### Phase 2: Verify Prerequisites

Check that the required CLI tools are installed:

```bash
which pandoc && pandoc --version | head -1
which mmdc && mmdc --version 2>&1 | head -1
```

- **pandoc** is required. If missing, instruct the user to run `brew install pandoc`.
- **mmdc** (mermaid-cli) is optional. If missing, warn that mermaid diagrams will remain as code blocks, then continue.

When `format=pdf`, also check for **weasyprint**:

```bash
which weasyprint && weasyprint --version 2>&1 | head -1
```

- **weasyprint** is required only when `format=pdf`. If missing, instruct the user to install it via `pip install weasyprint` or `brew install weasyprint`, then stop.

### Phase 3: Pre-process Mermaid Diagrams

For each markdown file that contains ` ```mermaid ` fenced blocks:

1. Create a temp directory for diagram PNGs.
2. Extract each mermaid block to a `.mmd` file.
3. **Clean the mermaid code** before rendering: strip source citation links (`[📄](file:line)`), `[Source: ...]` references, and normalize line endings. This prevents documentation artifacts from appearing as literal text in rendered diagrams.
4. Render via: `mmdc -i <input>.mmd -o <output>.png -b white -w 1200 -s 2`
5. Replace the fenced block in the markdown with `![Diagram](<output>.png)`.
6. If mmdc fails for a block, keep the original code block unchanged.

### Phase 4: Pandoc Conversion

**Output directory**: Create a `docx/` (or `pdf/`) subdirectory inside the docs directory (e.g., `legacylift-docs/docx/`) and write all output files there. If the subdirectory already exists, reuse it.

**Important — No Pandoc-generated TOC**: Do **not** use the `--toc` flag. The markdown source files already contain their own `## Table of Contents` sections with navigable links. Adding `--toc` would produce a duplicate Table of Contents in the output.

#### Individual mode (default)

Loop over each `.md` file independently:

1. For each file, create a working copy in the temp directory.
2. Prepend a YAML metadata block using the document's own filename (without extension) as the title:
   ```yaml
   ---
   title: "<document-name>"
   subtitle: "Generated by LegacyLift AI by CapTech"
   ---
   ```
3. Run Pandoc to produce the output file inside the `docx/` (or `pdf/`) subdirectory.

   **Word output:**
   ```bash
   pandoc <stem>.md -o <docs-dir>/docx/<stem>.docx \
     --reference-doc=tools/templates/reference.docx \
     --resource-path=<temp-dir>
   ```

   **PDF output:**
   ```bash
   DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib \
   pandoc <stem>.md -o <docs-dir>/pdf/<stem>.pdf \
     --pdf-engine=weasyprint \
     --resource-path=<temp-dir>
   ```

   > **macOS note**: The `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib` prefix is required so weasyprint can find Homebrew-installed Pango/GLib libraries.

4. If the reference doc is not found at `tools/templates/reference.docx`, omit `--reference-doc` and proceed with Pandoc defaults.

#### Consolidated mode (`mode=consolidated`)

1. Concatenate all markdown files (sorted) with `\newpage` separators between them.
2. Prepend a YAML metadata block for the title page:
   ```yaml
   ---
   title: "<repo-name> – Repository Documentation"
   subtitle: "Generated by LegacyLift AI by CapTech"
   ---
   ```
3. Write the combined markdown to a temp file.
4. Run Pandoc to produce the output file inside the `docx/` (or `pdf/`) subdirectory:

   **Word output:**
   ```bash
   pandoc combined.md \
     -o <docs-dir>/docx/<repo-name>_documentation.docx \
     --reference-doc=tools/templates/reference.docx \
     --resource-path=<temp-dir>
   ```

   **PDF output:**
   ```bash
   DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib \
   pandoc combined.md \
     -o <docs-dir>/pdf/<repo-name>_documentation.pdf \
     --pdf-engine=weasyprint \
     --resource-path=<temp-dir>
   ```

5. If the reference doc is not found at `tools/templates/reference.docx`, omit `--reference-doc` and proceed with Pandoc defaults.

### Phase 5: Validate and Report

1. Confirm all output files exist and report their sizes.
2. Report:
   - **Output format**: Word (.docx) or PDF (.pdf)
   - **Export mode**: Individual or Consolidated
   - **Number of files generated**
   - **Output directory path**
   - **List of output file paths**
   - **Mermaid diagram stats**: Number rendered vs. skipped
3. Clean up any temp files.

## Output

All output files are written to a `docx/` (or `pdf/`) subdirectory inside the docs directory:

```
repos/my_project/legacylift-docs/
├── docx/                          ← generated output
│   ├── 00-EXECUTIVE-SUMMARY.docx
│   ├── 01-SYSTEM-ARCHITECTURE.docx
│   └── ...
├── 00-EXECUTIVE-SUMMARY.md        ← original source (untouched)
├── 01-SYSTEM-ARCHITECTURE.md
└── ...
```

- **Individual mode** (default): One `.docx` or `.pdf` file per markdown source file, each with its own title page. The document's existing Table of Contents from the markdown is preserved as-is (no duplicate Pandoc TOC).
- **Consolidated mode**: A single `<repo-name>_documentation.docx` or `<repo-name>_documentation.pdf` file containing:
  - Title page with repository name and CapTech branding
  - All documentation sections with page breaks between them
  - Mermaid diagrams rendered as PNG images
  - Properly styled headings, tables, code blocks, and lists
